## Project Overview

ECP Calculator is a React web app for calculating Energy Conservation Points (ECP) under NBC 2020. Builders and building officials use it to determine if a residential design meets Tier 2 (10 pts) or Tier 3 (20 pts) prescriptive energy performance thresholds for Climate Zone 6 (Nova Scotia).

## Architecture

- **All state in App.jsx** — no context providers, no state libraries
- **YAML-driven data pipeline** — material properties in YAML, build script generates JSON, React app imports JSON
- **CSS variables for theming** — dark mode inverts gray scale via custom properties
- **Progressive disclosure** — wall builders show only relevant fields per wall or foundation type
- **Dual wall input modes** — direct RSI selection or assembly-based calculation, for both above-ground and below-grade walls
- **Client-side Excel export** — ExcelJS dynamically imported, no server component
- **Print telemetry** — `server/` (Express + Postgres) records an anonymous event on every "Save / Print" click. It records the tier, point totals, and category/wall selections (indices and enum-like fields) only. It does **not** record the Project / Address, Permit Number, or Applicant fields, IP addresses, or any other free-text/identifying input. See [docs/infrastructure.md](docs/infrastructure.md#print-telemetry).

## Data Flow

```
data/materials/*.yaml → scripts/generate.js → src/data/generated/*.json → ecpData.js → React components
```

After editing any YAML file, run `npm run generate` to regenerate JSON, then `npm test` to validate.

## Wall Types

The wall builder supports five assembly types:
- **Single stud** (wood) — parallel-path calculation + boundary layers
- **Double stud** (wood) — two stud rows + isothermal gap
- **Service wall** — interior 2x4 service cavity (toggle on single/double stud)
- **Steel frame** — NBC K-factor weighted method
- **ICF** — insulated concrete forms, pure series sum

### Foundation types

The below-grade wall builder (`BelowGradeWallBuilder.jsx`) supports four foundation types, all calculated by `foundationWallRsi()` in `scripts/compute.js` as a series sum of layers with the framed layer by parallel path. Layers counted: the materials plus the interior air film (0.12). No exterior air film and no soil (NBC 2020 Note A-9.36.2.8.(1)).

- **Poured Concrete** - 200 mm or 250 mm wall (0.0004 RSI/mm); optional exterior insulation (XPS, EPS, mineral wool; no polyiso in ground contact), optional interior continuous insulation (XPS, EPS, Polyiso, closed-cell spray foam), optional interior 2x4/2x6 stud wall, gypsum or no finish
- **Concrete Block** - 190 mm block with the 14 core options of Table A-9.36.2.4.(1)-D (normal-weight: empty, perlite or vermiculite cores; medium- and light-weight: those three plus EPS beads or EPS inserts; limestone aggregate with perlite), then the same optional layers as poured concrete
- **ICF** - the `icf.yaml` forms (2-1/2" to 4-1/4" per side) with the 152.4 mm core, plastic ties only; finish locked to gypsum
- **Permanent Wood Foundation** - 12.5 mm plywood sheathing (0.109) plus a 2x6 / 2x8 / 2x10 stud wall at 8", 12" or 16"; the cavity % is derived (2x8 and 2x10 reproduce Table A-9.36.2.8.(1)-B; 2x6 reproduces the 38 x 140 rows of Table A-9.36.2.8.(1)-A)

Gypsum (1/2", counted as 0.0775, the Note A-9.36.2.8.(1) value; the above-ground builder uses 0.08) is on by default and is forced on for ICF and whenever interior continuous insulation is present (9.10.17.10.(1)). A "Stud wall held off the concrete" checkbox appears only for the 2x6 R20 batt and swaps its 3.34 for 3.52 (Table A-9.36.2.8.(1)-A Note (3)).

Cavity percentages (the cavity share of the framed layer, from `framing.yaml` and `foundation.yaml`):

| Framed layer | Source table | Spacing -> cavity % |
|---|---|---|
| Above-ground wood wall | Table A-9.36.2.4.(1)-A | 16" 77, 19.2" 78.5, 24" 80 |
| Basement stud wall inside a concrete or block wall | Table A-9.36.2.4.(1)-A (basement row) | 16" 84, 19.2" 85.5, 24" 87 |
| Permanent wood foundation | Table A-9.36.2.8.(1)-B (reproduced) | 8" 76, 12" 81, 16" 84 |

## ECP Categories

Eight scoring categories, each with point thresholds from NBC 2020 Tables 9.36.8.4–9.36.8.10:
- Above-Ground Walls, Below Grade Walls, Windows/Doors, Airtightness
- Hot Water (Electric), Hot Water (Non-Electric) — mutually exclusive
- Ventilation (HRV/ERV), Heated Volume

Above-Ground Walls and Below Grade Walls are builders (`type: 'wallBuilder'` and `type: 'belowGradeBuilder'`), the rest are `CategoryCard`s. Below Grade Walls levels come from `thresholds.json` (`belowGrade`: 3.09 -> 0.2, 3.46 -> 0.8, 3.90 -> 1.4; `minBelowGradeRsi`: 2.98). Its Select RSI list starts with a 2.98 / 0-point floor button (the code minimum of Table 9.36.2.8.-B) ahead of the three point levels, so `simpleIndex` 0 is the floor. Below-grade RSI is rounded to 2 decimals before it is compared with a level or the minimum, the same rule as `getWallPoints()`.

## Versioning

**Before every push to remote, always:**

1. Bump the patch version in `package.json` (e.g. `1.0.1` → `1.0.2`)
2. Update the constants at the top of `src/App.jsx` to match — both the version number and today's date:
   ```jsx
   const APP_VERSION = '1.0.2'
   const APP_UPDATED = 'YYYY-MM-DD'
   ```
   `APP_VERSION` is also what the print telemetry records as `app_version`.
3. On a minor or major bump, update the "Generated by ECP Calculator vX.Y" footer in `src/components/PrintSummary.jsx` too.

Use semantic versioning: patch (`x.x.N`) for bug fixes and minor updates, minor (`x.N.0`) for significant new features.

## Conventions

- When modifying YAML materials, always regenerate JSON and commit both
- When modifying thresholds in `generate.js`, regenerate and run tests
- CSS changes should use existing custom properties where possible
- Both wall builders use FieldGroup numbered cards for visual grouping
- ExcelJS is a dev dependency but dynamically imported at runtime (code-split)
